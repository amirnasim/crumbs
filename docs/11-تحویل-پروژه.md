## 1. مقدمه

این سند اقلام رسمی تحویل پروژه Crumbs را مشخص می‌کند. هدف آن این است که تیم تحویل‌گیرنده بداند چه بخش‌هایی همراه پروژه ارائه شده‌اند، وضعیت فعلی نرم‌افزار چیست، کدام موارد پیش از Go-Live باید توسط کارفرما یا تیم زیرساخت فراهم شوند و چه مواردی خارج از محدوده تحویل نرم‌افزار قرار دارند.

Crumbs از منظر توسعه نرم‌افزار و مستندات در وضعیت Production Ready تحویل می‌شود. این وضعیت به معنی آماده بودن کد، ساختار پروژه، مستندات، تست‌ها و زیرساخت قابل استقرار است؛ اما Go-Live همچنان به آماده‌سازی محیط Production، تنظیم secrets، دامنه، SSL، سرویس‌های خارجی و اجرای چک‌لیست‌های استقرار نیاز دارد.

## 4. نیازمندی‌های محیط Production

موارد زیر مسئولیت زیرساخت، کارفرما یا تیم عملیاتی محیط Production هستند. نبود یا آماده نبودن این موارد نقص نرم‌افزار محسوب نمی‌شود.

| مورد | مسئول تأمین |
| --- | --- |
| Domain | کارفرما یا مالک پروژه |
| DNS | کارفرما، مالک دامنه یا تیم زیرساخت |
| VPS server | کارفرما یا تیم زیرساخت |
| PostgreSQL instance | تیم زیرساخت یا مسئول استقرار |
| Redis | تیم زیرساخت یا مسئول استقرار |
| SSL certificate | مالک دامنه یا مسئول استقرار |
| `SECRET_KEY` | مسئول استقرار یا مدیر فنی |
| `ALLOWED_HOSTS` | مسئول استقرار یا مدیر فنی |
| `CSRF_TRUSTED_ORIGINS` | مسئول استقرار یا مدیر فنی |
| `ZARINPAL_MERCHANT_ID` | کارفرما یا مالک درگاه پرداخت |
| SMS credentials | کارفرما یا مالک حساب پیامک |
| SMTP credentials | کارفرما یا مالک حساب ایمیل |
| Backup storage | کارفرما یا تیم زیرساخت |

این موارد باید پیش از Go-Live نهایی در `.env` و زیرساخت Production تنظیم و اعتبارسنجی شوند.

## 5. موارد خارج از محدوده تحویل

موارد زیر بخشی از بسته نرم‌افزاری تحویل‌شده نیستند، مگر اینکه در قرارداد جداگانه تعریف شوند:

- خرید دامنه
- تهیه VPS
- دریافت Merchant ID
- تهیه SMS account
- تهیه Email account
- تنظیم DNS
- تهیه SSL خارج از فرآیند استقرار مستندشده
- عملیات DevOps واقعی در محیط Production
- مانیتورینگ Production پس از Go-Live
- نگهداری پس از تحویل
- پاسخ‌گویی عملیاتی بلندمدت
- تأمین secrets تولید
- مدیریت حساب‌های تجاری سرویس‌های خارجی

## 6. اقدامات پیشنهادی پس از تحویل

1. آماده‌سازی VPS بر اساس `docs/VPS_LAUNCH_RUNBOOK.md`.
2. تنظیم environment variables و secrets بر اساس راهنمای استقرار و چک‌لیست‌های عملیاتی.
3. تنظیم Domain و DNS برای محیط Production.
4. راه‌اندازی SSL و بررسی مسیرهای HTTPS.
5. اجرای deploy بر اساس `docs/06-راهنمای-استقرار.md`.
6. بررسی health endpointها شامل `/health/` و `/ready/`.
7. ایجاد superuser برای پنل مدیریت.
8. اجرای `docs/LAUNCH_CHECKLIST.md`.
9. اجرای `docs/LAUNCH_TEST_PLAN.md`.
10. انجام Go-Live پس از تأیید کامل محیط Production.

## 8. جمع‌بندی

بسته نرم‌افزاری Crumbs از منظر توسعه، ساختار پروژه، مستندات رسمی، راهنمای استقرار، راهنمای توسعه، مستندات Database، مستندات API، راهنمای تست و اسناد عملیاتی آماده تحویل است.

موفقیت Go-Live وابسته به تکمیل آماده‌سازی محیط Production، تنظیم سرویس‌های خارجی، اجرای چک‌لیست‌های launch، تأیید health endpointها و انجام تست‌های نهایی در محیط واقعی است. این سند وضعیت تحویل نرم‌افزار را مشخص می‌کند و نباید جایگزین اجرای فرآیند استقرار و کنترل‌های عملیاتی شود.
